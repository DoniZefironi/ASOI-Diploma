# Инструкция по установке, развёртыванию и запуску программного продукта «АСОИ»

Документ описывает полный пошаговый процесс установки необходимого программного
обеспечения и развёртывания веб-приложения **АСОИ** (backend на NestJS, frontend
на Next.js, база данных PostgreSQL) на «чистой» машине под управлением Windows
10/11 с помощью **Docker Desktop** и **Docker Compose**.

## 1. Краткое описание системы

Приложение состоит из трёх контейнеризованных сервисов, описанных в файле
`docker-compose.yml`:

| Сервис | Технология | Контейнер | Порт |
|---|---|---|---|
| `db` | PostgreSQL 15 | `asoi_diploma_db` | внутренний (5432, не публикуется наружу) |
| `backend` | NestJS 11 (Node.js 18) | `asoi_diploma_backend` | `2904` |
| `frontend` | Next.js 15 (Node.js 18) | `asoi_diploma_frontend` | `3000` |

После запуска приложение доступно по адресам:

- **Веб-интерфейс:** http://localhost:3000
- **REST API + Swagger-документация:** http://localhost:2904/api
- **Проверка состояния backend:** http://localhost:2904/health

## 2. Системные требования

- ОС: Windows 10/11 (64-бит), сборка с поддержкой WSL2 (рекомендуется); также
  подходит Linux/macOS — шаги аналогичны, отличаются только команды установки
  Docker Desktop.
- Не менее **4 ГБ** свободной оперативной памяти (рекомендуется 8 ГБ).
- Не менее **5 ГБ** свободного места на диске (под образы и слои Docker).
- Подключение к Интернету (для загрузки образов Docker и npm-зависимостей при
  первой сборке).

## Шаг 1. Установка Docker Desktop

1. Перейдите на страницу https://www.docker.com/products/docker-desktop/ и
   скачайте установщик **Docker Desktop для Windows**.
2. Запустите скачанный файл `Docker Desktop Installer.exe` и следуйте
   инструкциям мастера установки. Оставьте включённой опцию **«Use WSL 2
   instead of Hyper-V»** (рекомендуется по умолчанию).

3. После установки перезагрузите компьютер, если установщик запросит это.
4. Запустите **Docker Desktop** из меню «Пуск». Дождитесь, пока в трее
   появится значок кита и статус в приложении изменится на **«Engine
   running»**.

5. Проверьте установку, открыв **PowerShell** и выполнив команды:

   ```powershell
   docker --version
   docker compose version
   ```

   Должны вывестись номера версий (например, `Docker version 27.x.x` и
   `Docker Compose version v2.x.x`).

## Шаг 3. Настройка файла окружения .env

В корне проекта находится файл-шаблон `.env.example`. Скопируйте его в новый
файл `.env`:

```powershell
Copy-Item .env.example .env
```

Файл `.env` содержит переменные, используемые `docker-compose.yml`:

```dotenv
# Настройки базы данных
POSTGRES_DB=Curs
POSTGRES_USER=postgres
POSTGRES_PASSWORD=4450
```

Для тестового/демонстрационного развёртывания значения из примера можно
оставить без изменений. При необходимости измените пароль на собственный —
он должен совпадать с тем, что будет использоваться при подключении к БД.

## Шаг 4. Запуск приложения

1. Находясь в корне проекта, выполните сборку и запуск всех контейнеров:

   ```powershell
   docker compose up -d --build
   ```

   Первый запуск занимает несколько минут — Docker скачивает базовые образы
   (`postgres:15`, `node:18-alpine`) и устанавливает все npm-зависимости
   backend и frontend.

2. После завершения сборки проверьте состояние контейнеров:

   ```powershell
   docker compose ps
   ```

   Ожидаемый результат — три запущенных контейнера:

   ```
   NAME                     STATUS
   asoi_diploma_db          Up (healthy)
   asoi_diploma_backend     Up (healthy)
   asoi_diploma_frontend    Up (healthy)
   ```

   > Контейнеру `asoi_diploma_backend` требуется до 60 секунд на старт
   > (ожидание готовности БД), `asoi_diploma_frontend` — до 40 секунд.
   > Если статус временно `(health: starting)` — это нормально, подождите.

3. На **чистом** volume базы данных при первом запуске PostgreSQL
   автоматически выполнит скрипт `database/init.sql` — будут созданы все
   таблицы и минимальный набор демонстрационных данных (курсы, разделы форума
   и т.д.). Если требуется загрузить **полный набор данных** — выполните
   [Шаг 5](#шаг-5-восстановление-базы-данных-из-дампа-с-данными).

## Шаг 5. Восстановление базы данных из дампа (с данными)

В архиве `deployment/database_dump.zip` (он же — файлы в папке
`deployment/database/`) находится **полный дамп базы данных** `Curs`
(44 таблицы со всеми накопленными данными: пользователи, курсы, заявки,
форум, олимпиады, хакатоны и т.д.).

1. Распакуйте `deployment/database_dump.zip`, если этого ещё не сделано — в
   результате появится файл `database_dump.sql`.

2. Убедитесь, что контейнер `asoi_diploma_db` запущен и имеет статус
   `healthy` (см. Шаг 4).

3. Восстановите дамп в контейнер:

   ```powershell
   Get-Content deployment\database\database_dump.sql -Raw | docker exec -i asoi_diploma_db psql -U postgres -d Curs
   ```

   Дамп создан с флагами `--clean --if-exists`, поэтому он сначала удаляет
   существующие таблицы, а затем создаёт их заново и заполняет данными —
   команду можно выполнять как на «чистой» БД (после `init.sql`), так и
   повторно.

4. Перезапустите backend, чтобы он корректно переподключился:

   ```powershell
   docker compose restart backend
   ```

> Подробности и альтернативный способ (через `restore_db.sh`) описаны в
> `deployment/database/README.md`.

## Шаг 6. Проверка работоспособности

1. Откройте браузер и перейдите по адресу **http://localhost:3000** — должна
   открыться главная страница приложения.

2. Перейдите по адресу **http://localhost:2904/api** — должна открыться
   страница Swagger с описанием REST API backend.

3. Проверьте состояние backend напрямую:

   ```powershell
   curl http://localhost:2904/health
   ```

   Ожидаемый ответ:

   ```json
   {"status":"ok","timestamp":"...","uptime":...}
   ```

4. **Проверка входа в систему.** Если был выполнен Шаг 5 (восстановление
   дампа), в системе доступна тестовая учётная запись администратора:

   - **Email:** `test_admin@asoi.edu`
   - **Пароль:** `Demo1234!`

   Откройте http://localhost:3000/auth, введите указанные данные и нажмите
   «Войти». После авторизации должна открыться панель с правами
   администратора (доступ к управлению курсами, пользователями и т.д.).

   Если дамп БД не восстанавливался (используется только `init.sql`), можно
   зарегистрировать новую учётную запись через страницу
   http://localhost:3000/auth (раздел регистрации) и убедиться, что
   регистрация и вход проходят успешно.

## Дополнительные (опциональные) модули

### A. Онлайн-компилятор (модуль «Компилятор»)

Раздел приложения, позволяющий выполнять код на JS, Python, C++ и Java в
изолированных Docker-контейнерах (через библиотеку `dockerode`). Для его
работы необходимо **один раз собрать вспомогательные sandbox-образы**:

```powershell
docker build -t sandbox-node:latest   -f backend/sandbox-images/Dockerfile.js     backend/sandbox-images
docker build -t sandbox-python:latest -f backend/sandbox-images/Dockerfile.python backend/sandbox-images
docker build -t sandbox-cpp:latest    -f backend/sandbox-images/Dockerfile.cpp    backend/sandbox-images
docker build -t sandbox-java:latest   -f backend/sandbox-images/Dockerfile.java   backend/sandbox-images
```

Без этих образов остальная часть приложения работает в полном объёме — не
будет работать только запуск кода в онлайн-компиляторе (вернётся ошибка
«Образ ... не найден»).

### Б. AI-модуль профориентации (Gemini API)

Модуль профориентации (`professional-orientation`) использует внешний API
**Google Gemini** для генерации рекомендаций. Чтобы включить эту функцию:

1. Получите API-ключ на странице https://aistudio.google.com/app/apikey.
2. Добавьте в файл `.env` строку:

   ```dotenv
   GEMINI_API_KEY=ваш_ключ
   ```

3. Добавьте переменную в секцию `environment` сервиса `backend` файла
   `docker-compose.yml`:

   ```yaml
     backend:
       environment:
         # ...существующие переменные...
         GEMINI_API_KEY: ${GEMINI_API_KEY}
   ```

4. Пересоберите и перезапустите backend:

   ```powershell
   docker compose up -d --build backend
   ```

Без ключа `GEMINI_API_KEY` всё остальное приложение работает в обычном
режиме — недоступна только генерация AI-рекомендаций по профориентации.

## Остановка и удаление приложения

- **Остановить** контейнеры (без удаления данных БД):

  ```powershell
  docker compose stop
  ```

- **Запустить заново** ранее остановленные контейнеры:

  ```powershell
  docker compose start
  ```

- **Остановить и удалить** контейнеры (данные БД в volume сохраняются):

  ```powershell
  docker compose down
  ```

- **Полностью удалить** контейнеры **и данные БД** (для повторного «чистого»
  развёртывания):

  ```powershell
  docker compose down -v
  ```

## Возможные проблемы и их решение

| Проблема | Решение |
|---|---|
| `docker compose` не распознаётся как команда | Убедитесь, что Docker Desktop запущен и установлена актуальная версия (Compose v2 встроен в Docker Desktop). Альтернатива — команда `docker-compose` (с дефисом). |
| Контейнер `asoi_diploma_backend` долго в статусе `starting` / `unhealthy` | Подождите 1–2 минуты — backend ждёт готовности БД. Проверьте логи: `docker compose logs backend`. |
| Порт `3000` или `2904` уже занят другим процессом | Освободите порт или измените порты в секции `ports:` файла `docker-compose.yml` (например, `"3001:3000"`), затем переоткройте приложение по новому порту. |
| При первом запуске нет демо-данных / нужных пользователей | Выполните восстановление дампа БД — [Шаг 5](#шаг-5-восстановление-базы-данных-из-дампа-с-данными). |
| Ошибка `password authentication failed for user "postgres"` | БД была инициализирована ранее с другим паролем. Выполните `docker compose down -v` (удалит volume с БД) и запустите `docker compose up -d --build` заново. |
| Не работает онлайн-компилятор | Соберите sandbox-образы — см. раздел [«Дополнительные модули»](#дополнительные-опциональные-модули), пункт А. |
