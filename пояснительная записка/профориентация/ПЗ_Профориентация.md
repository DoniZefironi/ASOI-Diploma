## 1. ВВЕДЕНИЕ

Разрабатываемой системой является веб-платформа профессиональной ориентации студентов в области информационных технологий — полнофункциональное веб-приложение, используемое в качестве цифрового инструмента профориентационного консультирования. Платформа позволяет пользователю пройти валидированные психологические тесты (тест Голланда RIASEC и тест Климова ДДО), получить персонализированный рейтинг подходящих IT-специальностей и сгенерировать индивидуальную дорожную карту профессионального развития. Приложение включает в себя модуль психологического тестирования с адаптивным интерфейсом, экспертную систему с механизмом прямого вывода на продукционных правилах и коэффициентами уверенности MYCIN, модуль генерации дорожных карт на основе большой языковой модели Google Gemini 2.0 Flash, историю тестирований пользователя, а также административный модуль управления тестами и аналитики. Приложение доступно на десктопных устройствах через веб-браузер.

Система имеет три категории пользователей. Студент использует платформу для прохождения психологических тестов, просмотра персонализированного рейтинга IT-специальностей с процентами совместимости, изучения своего психологического профиля и визуализации личностных черт, запроса дорожных карт обучения по выбранным специальностям, а также для просмотра истории предыдущих тестирований. Ментор выполняет функции сопровождения студентов: просмотр результатов тестирований подопечных, анализ агрегированной статистики прохождения тестов и консультирование по результатам. Администратор осуществляет полное управление платформой: настройка конфигураций тестов, управление базой знаний специальностей, управление пользователями и их ролями, просмотр системной аналитики.

## 2. АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

### 2.1. Описание предметной области

Предметная область данного проекта охватывает сферу цифровой профессиональной ориентации в IT-образовании — процесс помощи студентам в выборе подходящей специализации в области информационных технологий посредством применения методов психологического тестирования и экспертных систем.

Исследования показывают, что более 60% студентов испытывают затруднения при определении подходящего направления для будущей карьеры. Рынок информационных технологий насчитывает свыше 200 специализаций, требующих принципиально различных навыков и психологических профилей, что делает задачу профориентации в IT-сфере особенно сложной.

Основные участники процесса профориентации:

**Студенты** — проходят психологические тесты, получают рекомендации по IT-специальностям, изучают персонализированные дорожные карты обучения, просматривают историю своих тестирований.

**Менторы (консультанты)** — сопровождают студентов, просматривают результаты тестирований, анализируют статистику и дают консультации по интерпретации результатов.

**Администраторы** — управляют конфигурациями тестов, базой знаний специальностей, пользователями и системой в целом, имеют доступ к полной аналитике.

Процесс работы системы включает следующие этапы:
1. Регистрация и авторизация пользователя
2. Прохождение теста Голланда (RIASEC, 30 вопросов)
3. Прохождение теста Климова (ДДО, 20 вопросов)
4. Автоматическое формирование вектора личностных черт (9 трейтов)
5. Запуск механизма прямого вывода (Forward Chaining) с коэффициентами MYCIN
6. Просмотр рейтинга рекомендованных IT-специальностей
7. Запрос и просмотр персонализированной дорожной карты обучения
8. Просмотр истории тестирований и динамики профиля

### 2.2. Обзор существующих решений

На рынке представлен ряд платформ для цифровой профориентации:

| Платформа | Достоинства | Недостатки |
|-----------|-------------|------------|
| Proforientation.ru | Отечественная платформа, опросники | Ориентирована на широкий рынок, нет специализации на IT |
| CareerExplorer | Психометрические тесты, западный рынок | Нет актуальных данных для СНГ, нет дорожных карт |
| Профилум | Российская платформа, широкий охват | Ориентирована на школьников, не охватывает IT-специализации |
| LinkedIn Career Explorer | Данные реального рынка труда | Нет психологического анализа, нет планов обучения |
| Coursera Career Academy | Интеграция с курсами | Нет психологического тестирования, только общие направления |

Анализ показывает, что ни одна из существующих платформ не сочетает в себе: научно обоснованные психометрические методики, механизм экспертного вывода на продукционных правилах, специализацию именно на IT-направлениях и генерацию персонализированных дорожных карт обучения.

### 2.3. Обоснование разработки

Разработка собственной платформы обоснована следующими факторами:
- высокий спрос на доступные цифровые инструменты профориентации в IT-сфере;
- необходимость применения научно обоснованных психометрических методик (тест Голланда, тест Климова);
- отсутствие готовых решений с полным циклом: от психологического анализа до конкретного плана обучения;
- возможность использования современных технологий экспертных систем и генеративного ИИ;
- возможность гибкой адаптации базы знаний под актуальный рынок IT-специальностей.

## 3. ПОСТАНОВКА ЗАДАЧИ

### 3.1. Цель и задачи проекта

**Цель проекта:** разработать веб-платформу профессиональной ориентации студентов в области информационных технологий, которая на основании результатов психологических тестов строит профиль личности и предлагает персонализированные рекомендации по выбору IT-специальности с автоматически генерируемой дорожной картой обучения.

**Задачи:**
1. Провести анализ предметной области и требований к системе
2. Спроектировать архитектуру системы и базы данных
3. Реализовать серверную часть на основе NestJS с RESTful API
4. Разработать клиентскую часть на Next.js с интерактивным UI
5. Реализовать модуль психологического тестирования (тест Голланда, тест Климова)
6. Разработать экспертную систему с механизмом прямого вывода и коэффициентами уверенности MYCIN
7. Сформировать базу знаний с профилями IT-специальностей (90+ профессий)
8. Интегрировать Google Gemini 2.0 Flash для генерации персонализированных дорожных карт
9. Реализовать административный модуль управления тестами и аналитики
10. Развернуть систему с использованием Docker

### 3.2. Требования к системе

**Функциональные требования:**

*Управление пользователями:*
- Регистрация новых пользователей с верификацией через капчу
- Аутентификация по email и паролю с использованием JWT
- Разграничение доступа на основе ролей (RBAC)
- Управление профилем пользователя

*Модуль тестирования:*
- Прохождение теста Голланда (RIASEC): 30 вопросов в формате «да/нет»
- Прохождение теста Климова (ДДО): 20 вопросов с выбором из двух вариантов
- Сохранение результатов тестирования в базе данных
- Автоматический подсчёт баллов по категориям
- История прохождения тестов с привязкой к дате

*Экспертная система:*
- Формирование девятимерного вектора личностных черт (logical, analytical, technical, creative, social, managerial, research, detail, risk)
- Механизм прямого вывода (Forward Chaining) на 70+ продукционных правилах
- Объединение коэффициентов уверенности методом MYCIN
- Ранжирование IT-специальностей по проценту совместимости
- Формирование психологического профиля пользователя из 12 архетипов

*Дорожные карты:*
- Генерация персонализированных планов обучения через Google Gemini 2.0 Flash
- Структура дорожной карты: 4–5 фаз с целями, ресурсами и контрольными точками
- Резервный уровень шаблонной генерации при недоступности API
- Сохранение сгенерированных дорожных карт в базе данных

*Административный модуль:*
- Управление конфигурациями тестов (добавление, редактирование, активация)
- Управление вопросами тестов
- Просмотр агрегированной аналитики по результатам пользователей
- Управление пользователями и ролями

**Нефункциональные требования:**
- Веб-интерфейс, доступный через браузер без установки ПО
- Время отклика API не более 500 мс при нормальной нагрузке (без учёта вызова Gemini API)
- Поддержка современных браузеров (Chrome, Firefox, Edge)
- Контейнеризация приложения для простого развёртывания
- Документация API (Swagger)

### 3.3. Роли пользователей

Система поддерживает три основные роли:

**ADMIN (Администратор)**
- Полный доступ ко всем функциям системы
- Управление пользователями и их ролями
- Управление конфигурациями тестов и базой знаний
- Просмотр системной аналитики
- Модерация содержимого платформы

**MENTOR (Ментор / Консультант)**
- Просмотр результатов тестирований студентов
- Анализ агрегированной статистики прохождения тестов
- Просмотр профилей подопечных студентов
- Консультирование по интерпретации результатов

**STUDENT (Студент)**
- Прохождение психологических тестов
- Просмотр персонализированных рекомендаций по IT-специальностям
- Запрос и просмотр дорожных карт обучения
- Просмотр истории тестирований и своего профиля

## 4. ПРОЕКТИРОВАНИЕ СИСТЕМЫ

### 4.1. Общая архитектура

Система построена по трёхзвенной архитектуре клиент-сервер:

```
┌─────────────────────────────────────────────┐
│              Клиентский браузер              │
│        Next.js 15 / React 19 / TypeScript    │
└───────────────────┬─────────────────────────┘
                    │ HTTP/REST (JSON)
┌───────────────────▼─────────────────────────┐
│              Сервер приложений               │
│         NestJS 11 / Node.js / TypeORM        │
│   Модули: Auth, Users, ProfOrientation,      │
│   InferenceEngine, Roadmap, Admin            │
│                    │                         │
│         Google Gemini 2.0 Flash API          │
└───────────────────┬─────────────────────────┘
                    │ SQL (TypeORM)
┌───────────────────▼─────────────────────────┐
│              База данных                     │
│              PostgreSQL 16                   │
└─────────────────────────────────────────────┘
```

> **[РИСУНОК 1 — Общая архитектура системы]**

Все компоненты системы развёртываются в Docker-контейнерах и управляются через Docker Compose. Экспертные вычисления выполняются на стороне сервера, клиент отвечает за отображение результатов и интерактивный интерфейс тестирования.

### 4.3. Диаграммы последовательностей

#### 4.3.1. Авторизация пользователя

> **[РИСУНОК 2 — Диаграмма последовательности: Авторизация]**
> *(файл: diagrams/seq_01_authorization.puml)*

Процесс авторизации включает следующие шаги:
1. Пользователь открывает страницу `/auth` и вводит учётные данные
2. Клиент выполняет валидацию формы (проверка формата email, непустых полей)
3. При успешной валидации отправляется POST-запрос `/auth/login` с email и паролем
4. `AuthController` принимает запрос и обращается к базе данных для поиска пользователя
5. При нахождении пользователя выполняется сравнение хеша пароля через `bcrypt.compare`
6. В случае успеха генерируется JWT-токен, содержащий `userId`, `email` и `roles`
7. Токен сохраняется в `localStorage`, пользователь перенаправляется на главную страницу

#### 4.3.2. Проверка аутентификации

> **[РИСУНОК 3 — Диаграмма последовательности: Проверка аутентификации]**
> *(файл: diagrams/seq_02_authentication.puml)*

При переходе на защищённую страницу:
1. `ProtectedRoute` извлекает токен из `localStorage`
2. При отсутствии токена — редирект на `/auth`
3. Декодируется payload токена, проверяется роль пользователя
4. Если роль недостаточна для маршрута — редирект на главную
5. Выполняется запрос к `GET /auth/debug` для верификации токена на сервере
6. `JwtAuthGuard` проверяет подпись и срок действия JWT
7. При истечении срока — токен удаляется, редирект на авторизацию

#### 4.3.3. Регистрация нового пользователя

> **[РИСУНОК 4 — Диаграмма последовательности: Регистрация]**
> *(файл: diagrams/seq_03_registration.puml)*

Процесс регистрации:
1. Пользователь заполняет форму: имя, фамилия, email, пароль
2. Проходит математическую капчу и подтверждает согласие с условиями
3. Клиент проверяет ответ капчи локально
4. Отправляется POST-запрос `/auth/register`
5. Сервер проверяет уникальность email
6. Пароль хешируется через `bcrypt` (saltRounds=12)
7. Пользователю автоматически присваивается роль `STUDENT`

#### 4.3.4. Прохождение теста Голланда (RIASEC)

> **[РИСУНОК 5 — Диаграмма последовательности: Тест Голланда]**
> *(файл: diagrams/seq_04_holland_test.puml)*

Студент переходит в раздел тестирования. `ProfOrientationController` обращается к `career_tests` и возвращает конфигурацию теста Голланда — 30 вопросов в формате «да/нет». Пользователь последовательно отвечает на вопросы, интерфейс сохраняет ответы в локальном состоянии. По завершении клиент отправляет POST `/professional-orientation/tests/submit` с массивом ответов. `ProfOrientationService` подсчитывает баллы по шести категориям RIASEC (R, I, A, S, E, C), сохраняет результаты в `professional_orientations` и немедленно запускает алгоритм вычисления трейтов.

#### 4.3.5. Прохождение теста Климова (ДДО)

> **[РИСУНОК 6 — Диаграмма последовательности: Тест Климова]**
> *(файл: diagrams/seq_05_klimov_test.puml)*

Аналогично тесту Голланда: клиент получает 20 вопросов с попарным выбором (А или Б), каждый вопрос противопоставляет два типа объектов труда. По завершении теста результаты по пяти категориям Климова (ЧЧ, ЧТ, ЧП, ЧЗ, ЧХ) объединяются с результатами RIASEC для формирования итогового девятимерного вектора личностных черт.

#### 4.3.6. Механизм прямого вывода

> **[РИСУНОК 7 — Диаграмма последовательности: Механизм вывода]**
> *(файл: diagrams/seq_06_inference_engine.puml)*

После сохранения результатов тестирования `InferenceEngineService` выполняет следующую последовательность: нормализация сырых баллов в вектор трейтов [0;10], последовательный перебор 70+ продукционных правил базы знаний, отбор сработавших правил (все условия выполнены), объединение коэффициентов уверенности по формуле MYCIN: `CF_combined = CF_old + CF_new × (1 − CF_old)`. Результат — ранжированный список IT-специальностей с процентами совместимости. Специальности с CF×100 ниже 35% не включаются в выдачу.

## 5. РЕАЛИЗАЦИЯ СИСТЕМЫ

### 5.1. Серверная часть (Backend)

Серверная часть реализована на основе фреймворка **NestJS** с использованием TypeScript. Архитектура следует принципу разделения ответственности: каждый модуль содержит контроллер, сервис и сущности TypeORM.

**Аутентификация и авторизация** реализованы посредством:
- `LocalStrategy` (Passport) — проверка email/пароля при входе
- `JwtStrategy` — верификация JWT при каждом защищённом запросе
- `JwtAuthGuard` — декоратор-охранник для защищённых маршрутов
- `RolesGuard` + `@Roles()` — проверка роли пользователя

```typescript
// Пример защищённого маршрута с проверкой роли
@Post('tests/submit')
@UseGuards(JwtAuthGuard, RolesGuard)
@Roles('student')
async submitTest(
  @Request() req,
  @Body() dto: SubmitTestDto,
): Promise<OrientationResultDto> {
  return this.profOrientationService.submitTest(req.user.id, dto);
}
```

**Экспертная система** реализована в `InferenceEngineService`. База знаний загружается из файла `knowledgeBase.ts` при старте приложения. Вычисления выполняются синхронно на стороне сервера. Функция `runForwardChaining()` обходит все правила за O(N×M), где N — число правил (70+), M — число трейтов (9).

**API** полностью задокументировано через Swagger (`/api/docs`). Все эндпоинты принимают и возвращают JSON.

### 5.2. Клиентская часть (Frontend)

Клиентская часть реализована на **Next.js 15** с использованием App Router. Структура проекта:

```
src/
├── app/                    # Маршруты (страницы)
│   ├── auth/               # Авторизация / Регистрация
│   ├── tests/              # Прохождение тестов
│   │   ├── holland/        # Тест Голланда
│   │   └── klimov/         # Тест Климова
│   ├── results/            # Результаты анализа
│   ├── roadmap/            # Дорожные карты обучения
│   ├── history/            # История тестирований
│   ├── profile/            # Профиль пользователя
│   └── admin/              # Административная панель
├── features/               # Бизнес-логика страниц (React-компоненты)
│   ├── inference-engine/   # Клиентский движок вывода (предварительный расчёт)
│   └── knowledge-base/     # knowledgeBase.ts — база профилей специальностей
├── shared/                 # Общие утилиты, API-клиент
└── widgets/                # Переиспользуемые компоненты (Header, Sidebar)
```

Для запросов к API используется библиотека **SWR**, обеспечивающая кэширование и автоматическую повторную загрузку. Механизм вывода дублируется на клиенте в `inferenceEngine.ts` для мгновенного отображения предварительных результатов без ожидания серверного ответа.

### 5.3. База данных

База данных **PostgreSQL** инициализируется скриптом `database/init.sql`. Схема управляется через **TypeORM** с синхронизацией сущностей. При первом запуске сервера модуль `seed` автоматически заполняет таблицы `career_tests` и `test_questions` конфигурациями тестов Голланда и Климова.

Для хранения сложных структур используется тип **JSONB**:
- `career_tests.questions` — массив вопросов теста
- `career_tests.categoryMeta` — метаданные категорий с профессиями
- `professional_orientations.testResult` — полный вектор трейтов и баллы по категориям
- `learning_roadmaps.phases` — структурированные фазы дорожной карты

Созданы индексы для оптимизации:
- По `userId` в `professional_orientations` и `learning_roadmaps`
- По `testId` в `test_questions`
- По `email` в `users`

### 5.4. Ключевые модули системы

#### Экспертная система (Inference Engine)

Модуль реализует механизм прямого вывода на продукционных правилах. База знаний содержит 70+ правил вида `ЕСЛИ (trait_1 >= x1 И trait_2 >= x2 ...) ТО специальность, CF = y`. Коэффициенты уверенности объединяются по формуле MYCIN:

```
CF_combined = CF_old + CF_new × (1 − CF_old)
```

Это обеспечивает накопление уверенности с убывающей отдачей — большое количество слабых правил не даёт неоправданно высокого итогового коэффициента.

> **[РИСУНОК 14 — Радарная диаграмма профиля личностных черт]**

#### Модуль тестирования

Тест Голланда (30 вопросов, «да/нет») оценивает шесть типов профессиональной направленности RIASEC. Тест Климова (20 вопросов, попарный выбор) классифицирует предпочтения по пяти типам объектов труда. Результаты двух тестов объединяются в девятимерный вектор трейтов через процедуру взвешенной нормализации.

> **[РИСУНОК 15 — Интерфейс прохождения теста Голланда]**

#### Модуль дорожных карт

`RoadmapService` формирует структурированный промпт для Google Gemini 2.0 Flash, включающий целевую специальность, психологический профиль и слабые стороны пользователя. Модель возвращает план обучения из 4–5 фаз. При недоступности Gemini API активируется резервный шаблонный генератор для распространённых специальностей (Frontend/Backend Developer, Data Scientist и др.).

> **[РИСУНОК 16 — Пример сгенерированной дорожной карты]**

#### Административный модуль

Администратор имеет доступ к панели аналитики, показывающей: распределение студентов по рекомендованным специальностям, среднее значение трейтов по всей базе пользователей, количество пройденных тестов по периодам, наиболее популярные дорожные карты.

> **[РИСУНОК 17 — Административная панель аналитики]**
